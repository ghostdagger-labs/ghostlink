# Visual fidelity

The original `docs/design/Ghostlink UI/Ghostlink Prototype.html` and its runtime are preserved. The original specification is archived separately; protocol corrections do not change the prototype.

The [Ghostlink brand document](../design/brand/Ghostlink%20Brand.dc.html) governs the current palette, two-node brand mark, and Figtree/Sora/JetBrains Mono typography. The original prototype remains authoritative for geometry: the 440px desktop modal, 380px narrow layout, 20/26px radii, 18px body inset, wallet rows, search, tabs, review cards, message panel, status chips, buttons and entry animation. React and Vue render the same classes and presentation data. The brand update changes no screens, controls, layouts or application behavior.

Allowed differences are explicit:

- Only source-backed, configured wallets appear. Logos come from wallet repositories and carry provenance/licenses; fabricated wallet names, counts and prototype monograms are not data sources.
- Source application/domain/network/account/capabilities and verified session data replace mock fields. Prototype relay status, simulated success/failure controls, device switches and navigation are removed.
- As of 2026-11-19, the default chooser contains only KasWare and Kastle, with no mobile shortcut. Search and category controls are hidden while the default list has only two wallets; configured wallets are displayed directly, with their installation badges. Mobile/hardware marketing entries are hidden. These intentional visibility changes follow the [integration decision](../roadmap/wallet-integrations.md); the archived prototype is unchanged.
- Explicitly configured Kaspium adds address entry, manual message transfer, signature entry/scanning and expiry regeneration using the prototype's existing account/input/QR/message treatments. Its development-only `/manual.html` harness retains coverage. QR images contain real bytes, a quiet zone and no center logo obscuring data. No invented pairing URI is shown.
- Backend verification controls success. Application session status is distinguished from connectivity. Actual request text can grow and scroll instead of being clipped.
- A fresh verified login closes the modal by default; `closeOnAuthenticate: false` keeps session details open. The account button reopens details and sign-out on demand. Test signing and balance refresh belong to the example's Wallet requests panel, not the shared modal. These completion changes apply equally to Vue and React.
- Availability/manual badges retain secondary text in light mode for contrast. Primary buttons, signed-out connect buttons and selected tabs retain the original neutral hierarchy using the new brand palette and existing shared button tokens. Violet is limited to links and the example’s unboxed brand marks. Focus rings use the neutral muted-text color, and the search field has one outer ring without an inner input outline. Wallet-row hover fills/borders and waiting indicators retain neutral interaction tokens with their original opacity, rather than a violet wash. Authenticated buttons use neutral brand surfaces and text, with account overrides honored in both themes. Warning colors and shadows retain their previous values.
- Functional icons use Lucide. The two-node brand SVG replaces only the existing example branding placeholders and signed-out connect icons, inside their original container footprints. The example’s marks are unboxed violet; connect-button marks inherit the button foreground. Its actual SVG geometry takes precedence over the brand document's inconsistent overlap prose. Wallet-specific marks reflect the actual chosen wallet; host-app icons and fallbacks remain unchanged.

Browser checks cover default/custom palettes in both themes, narrow/wide viewports, keyboard behavior, axe accessibility, and React/Vue consistency. Visual baselines are accepted only after reviewing the rendered UI against the brand document and the preserved geometry. Dynamic messages, expiry values and QR contents must be excluded from pixel-baseline assertions or fixed in a test-only harness; the production UI never fabricates these values.

To inspect the original through the dev server, open `/@fs/<absolute repository path>/docs/design/Ghostlink%20UI/Ghostlink%20Prototype.html`. The original runtime loads its own historical React/Babel/font services; this external loading is confined to the preserved prototype. Ghostlink itself ships its fonts locally.
